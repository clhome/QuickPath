## 2. P1-08:延迟恢复改为**条件式取得**操作级所有权

### 2.1 缺陷确认(报告描述与代码一致)

修改前 `spawn_restore_original_name()` 只在开头做一次:

```rust
if current_generation(&identity.fingerprint()) != generation { return; }
```

通过后该线程**不持有 `WpsInjectLease`**,却继续执行窗口复核、`CoCreateInstance`、
`find_wps_edit_element`、`focus_edit_element`、剪贴板粘贴与 `Ctrl+A` / `Ctrl+V` 等全局输入。
这正是报告描述的 check-then-act TOCTOU:检查与动作之间新注入可取得所有权并递增 generation,
两者仍会互相干扰。**仅在粘贴前再检查一次不能根治**(报告已指出),只是把窗口缩小。

### 2.2 落地:状态锁内的原子条件取得

`src/win32/uia.rs`:

- 新增 `WpsInjectLease::try_acquire_restore(fingerprint, expected_generation)`,
  在**同一次加锁**内同时校验:
  1. `state.holder.is_some()` → 拒绝(已有注入接管);
  2. `state.generations.get(fingerprint).copied() != Some(expected_generation)` → 拒绝
     (代次已过期 / 从未注入过 → fail-closed,**不把「无记录」当成代次 0 匹配**)。
  成功后登记 holder,**刻意不递增代次**(递增会让本次恢复自己的期望值立即失效)。
- 主注入 `try_acquire()` 语义不变(仍递增代次),两者共用底层状态但入口分离。
- 新增 `acquire_restore_lease(fingerprint, generation)` 作为**唯一取得点**,
  内部即为 `try_acquire_restore` 调用;单独成函数只为给测试一个确定性会合点(生产语义不变)。
- `spawn_restore_original_name()` 在 650ms 睡眠结束后**立即**取得所有权,
  并把变量 `_restore_lease` 绑到闭包外层作用域,活到整段动作结束
  (下划线前缀只抑制未使用告警,**不**禁用 `Drop`)。
  取不到即 `return` —— 不建 UIA 客户端、不查控件、不抢焦点、不碰剪贴板、不发按键。
- 既有的窗口身份复核、前台状态检查、「用户已手动输入新文件名」防覆盖保护**全部保留**
  (它们解决的是不同风险)。
- **两把 lease 职责保持独立**(报告第 3 节明确要求):WPS 操作级 lease 保护前台/键盘/UIA,
  剪贴板事务 lease 保护系统剪贴板,**刻意不合并**。

### 2.3 关键不变量与守卫

| 不变量 | 守卫 |
|---|---|
| holder 校验、代次校验、登记 holder 在同一临界区 | `test_wps_injection_wires_lease_and_generation_checks`:断言 `state.generations.get(fingerprint)`(而非 `current_generation()`)出现,且锁取得语句早于两处校验 |
| 恢复入口不递增代次 | 同上:断言该函数体内**无** `wrapping_add` |
| 取得点早于一切动作 | `test_wps_restore_wires_conditional_acquire_before_any_action`:逐个断言 `identity.verify()` / `CoCreateInstance` / `find_wps_edit_element` / `focus_edit_element` / `with_temporary_clipboard_text` / `simulate_ctrl_a_checked` / `simulate_ctrl_v_checked` 均晚于取得点 |
| 取不到即零动作 | 同上:取得点后窗口内必须出现 `return` |
| 取得后不得立即释放 | 同上:禁止 `drop(_restore_lease)` / `drop(restore_lease)`;要求绑定到 `let Some(_restore_lease) =` |

## 3. P1-08 的测试(报告必测 6 项 + 确定性会合点)

| # | 变异(报告指定) | 结果 |

| M4 | 允许 holder 已存在时继续 | ❌ `test_restore_lease_is_conditional...` |
| M5 | 恢复入口错误地递增 generation | ❌ `test_restore_lease_is_conditional...` + `test_wps_injection_wires...` |

### 6.1 M2 暴露的真实空洞(已当场修正,重要)

M2 第一次执行时**只**让 `test_restore_lease_is_conditional...` 变红(靠「未知指纹」那条断言),
而**真正**要为这个 TOCTOU 负责的源码守卫 `test_wps_injection_wires...` **没红** ——
原因是原有守卫只检查「函数体内出现过 `wrapping_add` / `holder.is_some()` 次数」,
无法区分「检查在锁内」还是「检查在锁外」。

修法:利用「`current_generation()` 自己会加锁」这一事实 —— 只要它出现在该函数体内,
就**证明**代次检查发生在临界区之外。故新增两条断言:
`!contains("current_generation(")` 且 `contains("state.generations.get(fingerprint)")`,
并断言状态锁取得语句早于 holder 与代次两处校验。修正后重跑 M2 必红。

> 这与上一轮的教训同源:**守卫只断言「字符串出现过 / 次数对」很容易变成空洞**;
> 必须断言**相对位置**(谁在谁的临界区内、谁早于谁)。
