## 2. P0-06：探测全生命周期的进程级独占 lease

### 2.1 根因与修复

报告指出：`ClipboardTransaction` 的原子检查只覆盖「单次 Win32 写入」，不覆盖「快照 → 清空 → 请求管理器 → 读回 → 恢复」整个生命周期。两次并发探测会各自快照（第二次快照到的已经是第一次写下的空文本），最终双双 fail-closed 放弃恢复，用户原始内容被静默丢掉。

修复：新增 `src/managers/probe_lease.rs` —— **TC / XYplorer 共用的进程级非阻塞独占 lease**：

```rust
static PROBE_IN_FLIGHT: AtomicBool = AtomicBool::new(false);

pub fn try_acquire() -> Option<ProbeLease> {
    PROBE_IN_FLIGHT
        .compare_exchange(false, true, Ordering::AcqRel, Ordering::Acquire)
        .ok()
        .map(|_| ProbeLease { _private: () })
}
impl Drop for ProbeLease {
    fn drop(&mut self) { PROBE_IN_FLIGHT.store(false, Ordering::Release); }
}
```

`explicit_probe::probe_with_snapshot()` 的**固定顺序**（每一步都不得越前）：

| 步骤 | 动作 | 失败结局 |
|---|---|---|
| 1 | 授权闸门 | `NotAuthorized`（零剪贴板触碰） |
| 2 | 失败冷却（`ipc::try_enter`，**不是**互斥） | `CoolingDown` |
| 3 | **`ProbeLease::try_acquire()`** | `AlreadyRunning`（零剪贴板触碰） |
| 4 | 快照身份核验（HWND/PID/类名/进程镜像/可见/顶层） | `NoForegroundTarget` |
| 5 | 管理器事务（`ClipboardTransaction::begin()` 及之后全部剪贴板操作） | `NoPath` / `Path` |

- lease 是**局部绑定**，`probe_with_snapshot` 的任何 `return` / panic 展开都会经 `Drop` 释放；
- 没有把 `ipc` 的失败冷却表改名当互斥（报告 §2.4 第 5 条）；
- UI 侧同时置灰两个入口：托盘菜单项（`explicit_probe_menu_ready` 含 `!is_in_flight()`）+ 吸附条按钮（`contains()` 读实时 `is_in_flight()`，绘制为 `…` 忙碌态）。

### 3.2 新的目标模型

```rust
pub struct TriggerSnapshot {
    pub hwnd_raw: usize,
    pub pid: u32,
    pub manager: ScriptedManager,
    pub captured_at: Instant,   // 仅用于诊断日志，**不作为可用性判据**
```

| 入口 | 快照生成时机 | 口径 | 单次消费 / 失效 |
|---|---|---|---|
| 托盘菜单 | `WM_RBUTTONUP`（`SetForegroundWindow` 之前） | **严格前台**：前台必须是该管理器，否则菜单项 `MF_GRAYED` | `PENDING_TRAY_TRIGGER` 在 `WM_COMMAND` 中 `take()`；菜单关闭（选中或取消）后 `clear_pending_tray_trigger()` |

## 8. 诚实偏差登记（不隐藏）

1. **吸附条不是严格前台触发**：吸附条是 `WS_EX_NOACTIVATE` 窗口，点击时前台必然是对话框，
   因此 `[TC]` / `[XY]` 采用「与当前对话框打开事件绑定的最近来源」语义（报告 §3 明确允许）。
   它**不设墙钟时限**，因此“十分钟前的记录”不会影响**托盘**菜单项（严格前台），
   但可能让**吸附条按钮**在该对话框内出现（前提是该管理器窗口仍然存活且身份逐项复核通过）。
   手册「管理器联动」页已如实标注。
2. **`AlreadyRunning` 不弹气泡**：重复点击属于用户误操作而非探测失败，只记结构化日志
   （`EXPLICIT_PROBE_ALREADY_RUNNING`），避免连续双击刷屏。
3. **托盘气泡依赖系统通知设置**：Windows 11 的专注助手 / 通知设置可能抑制气泡，
   因此“可见反馈”不保证在所有机器上都可见；结构化日志始终可用。
4. **本机无真实管理器**：TC / XYplorer / WPS 均未安装，因此快照冻结、身份核验、并发压力
   只能通过源码守卫 + 纯函数 + 桩窗口验证，真实管理器行为必须走真机清单。
5. **纪律偏离**：本轮有 5 处 `SOURCE.find(...)` 断点调整最初用 `python` 脚本经 `bash` 改写，
   违反了 AGENTS.md「文件改动强制使用 Agent 原生文件工具」；随后已全部改回 `edit` 工具重做。
   内容无损，特此登记。
