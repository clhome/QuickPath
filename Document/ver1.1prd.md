# 产品需求文档 (PRD)：QuickPath 任务栏状态监控模块 (v1.1)

---

## 1. 文档概述与产品定位

- **产品名称**：QuickPath 任务栏状态监控模块（Taskbar Monitor Extension）
- **所属主工程**：[QuickPath](file:///f:/git/gitea20250909/QuickPath/Cargo.toml)
- **文档版本**：v1.1.0（正式修订版）
- **目标平台**：Windows 10 (1809+) / Windows 11 (全版本，x86_64 / ARM64)
- **核心定位**：作为 QuickPath 的**内置可选扩展模块**（默认启用，支持在设置与托盘中彻底停用），为桌面用户提供极简、低开销、高可靠的 Windows 原生任务栏硬件状态看板。在普通用户权限（Standard User Rights）下运行，彻底告别内核驱动依赖。
- **设计哲学**：
  - **极限轻量，零冗余开销**：集成入 QuickPath 主程序后，模块启用状态下增量内存常驻 $\le 5\text{ MB}$（全局进程 Working Set 保持在 $15\sim 20\text{ MB}$ 内），增量 CPU 占用 $\le 0.05\%$；**模块停用时完全退出采集线程并释放句柄，达到绝对 0% CPU 与 0 MB 增量开销**。
  - **常驻精简，悬停丰富**：常驻任务栏仅展示高频核心数据，深层明细下沉至悬浮看板（Tooltip）。
  - **深度融入系统与主程序**：完美适配 Win10/Win11 浅色/深色主题，无缝协同 QuickPath 设置中心与托盘系统。
  - **坚若磐石，主动避让**：容忍锁屏、睡眠唤醒、多屏与 DPI 热插拔、Explorer 重启；**具备全屏应用自动隐匿避让能力，绝不遮挡游戏、全屏影音与演示**。

## 2. 核心指标与采集规格

所有指标严格选用 Windows 官方免特权用户态 API 与 PDH 性能计数器，杜绝任何 Ring 0 驱动注入风险。

### 2.1 指标采集矩阵

| 模块分类 | 指标项 | 展示格式 | 底层 API / 数据源 | 计算与单位转换逻辑 |
| :--- | :--- | :--- | :--- | :--- |
| **网络** | 实时上传速率 | `↑ 1.2` (省略单位) | `GetIfTable2` (IP Helper API) | 统计所有物理网卡发送差值；面板**统一采用 Mbps** 并**省略单位字符**，保留 1 位小数；Tooltip 显示完整 Mbps 与 MB/s |
| **网络** | 实时下载速率 | `↓ 3.5` (省略单位) | `GetIfTable2` (IP Helper API) | 过滤虚拟与回环网卡，统计接收差值；**统一采用 Mbps** 并**省略单位字符**；宽度缩减 40% |
| **计算** | CPU 总占用率 | `C: 18%` | `GetSystemTimes` | 计算采样周期内系统内核与用户时间占比：$(1.0 - \frac{\Delta \text{Idle}}{\Delta \text{Kernel} + \Delta \text{User}}) \times 100\%$ |
| **计算** | GPU 综合利用率 | `G: 32%` | PDH 计数器：`\GPU Engine(*)\Utilization Percentage` | 聚合采样当前活跃 GPU 的 3D 与 Compute 引擎峰值利用率；无独显/核显时优雅降级隐藏或显示 `--%` |
| **存储** | 物理内存利用率 | `M: 42%` | `GlobalMemoryStatusEx` | 提取 `MEMORYSTATUSEX.dwMemoryLoad`，计算已用内存占比 |
| **存储** | 磁盘实时读写与吞吐 | `D: 3%` | PDH 计数器：`\PhysicalDisk(_Total)\% Disk Time` | 采集所有物理磁盘的综合 I/O 活动时间百分比；Tooltip 细化采集读写带宽 |
| **显存 (Tooltip)** | GPU 专有显存占用 | `显存: 3.8/8.0 GB` | DXGI 接口：`IDXGIAdapter3::QueryVideoMemoryInfo` | 查询主显卡硬件专有显存（Dedicated VRAM）及共享显存分配详情 |
| **环境 (Tooltip)** | 电池状态与续航 | `98% (接通电源)` | `GetSystemPowerStatus` | 读取电池电量百分比、充放电状态及剩余估算使用时间；台式机设备不显示 |
| **系统 (Tooltip)** | 系统连续运行时间 | `运行: 3天 14时` | `GetTickCount64` | 格式化系统真实启动运行总时长，不受 Windows 10/11“快速启动”假关机欺骗 |
| **诊断 (Tooltip)** | 资源消耗 Top 1 进程 | `Top: chrome (18%)` | `GetProcessTimes` + 采样比对缓存 | 后台 Worker 维持秒级差值计算缓存；悬停 Tooltip 展开时**零延迟直接读取**，杜绝卡顿与盲目快照 |

### 2.2 虚拟网卡精准过滤策略

针对开发者与重度用户常驻 Hyper-V、WSL、VMware、Docker 及各类 VPN（WireGuard、Tailscale、Clash 等）场景，采集引擎按以下优先级过滤：
1. 过滤 `MIB_IF_ROW2.Type == IF_TYPE_SOFTWARE_LOOPBACK`；
2. 过滤 `MIB_IF_ROW2.OperStatus != IfOperStatusUp`（非联通状态网卡）；
3. 检查网卡友好描述 `Description`，忽略包含关键词的虚拟适配器：`Virtual`, `Hyper-V`, `VMware`, `VirtualBox`, `Loopback`, `TAP`, `TUN`, `Tailscale`, `ZeroTier`, `Wsl`；
4. 汇总剩余真实物理适配器（以太网、Wi-Fi）的瞬时读写差值。

## 3. 界面交互与排版规范

### 3.1 任务栏常驻面板布局

采用两行紧凑栅格布局，高度自适应任务栏高度（默认 32~40px），**由于网速省去单位后缀，三列总宽度大幅收窄至 115~135px 极紧凑尺寸**。

```text
┌───────────────────────────────────────────┐
│  ↑  1.2     C: 19%    G: 32%              │  <- 第一行：上传 Mbps (隐藏单位) | CPU% (微条) | GPU%
│  ↓  3.5     M: 42%    D:  3%              │  <- 第二行：下载 Mbps (隐藏单位) | 内存% (微条) | 磁盘吞吐
└───────────────────────────────────────────┘
```

- **网速数值精简规则**：
  - 统一换算为比特单位 `Mbps`，完全隐藏 `Mbps` 文字后缀，仅保留方向前缀 `↑` 与 `↓`；
  - 速率 $< 100$ 时保留 1 位小数（如 `0.2`、`12.5`、`98.4`），速率 $\ge 100$ 时按整数显示（如 `125`、`980`），实现固定字符宽度对齐；
  - 网络列宽度由原来的 ~65px 锐减至 ~32px，整体面板节省近 40% 任务栏空间。
- **动态列自适应收缩引擎（按勾选项动态计算宽度）**：
  - 指标按自然对齐逻辑编排为 3 个逻辑列：
    - **网络列**（占 1 列，行1为上传、行2为下载；由 `show_network` 独立控制）；
    - **算力/内存列**（行1为 CPU，行2为 内存；分别由 `show_cpu` 和 `show_memory` 控制）；
    - **扩展设备列**（行1为 GPU，行2为 磁盘；分别由 `show_gpu` 和 `show_disk` 控制）；
  - 当某列中的两个指标均未勾选时，该列**完全剔除并不占任何像素**；
  - 面板宽度随勾选列数（1 列 / 2 列 / 3 列）由 **~40px $\to$ ~85px $\to$ ~130px** 动态平滑自适应，绝不留多余空白。
- **微型指示条**：在 CPU、内存百分比数值下方渲染高度为 2px 的动态色块，超过 85% 呈现警戒黄色，超过 95% 呈现警示红色。
- **实时历史波形图（采样周期黄金标准：15~20 次 / 15~20 秒）**：
  - **周期合理性论证**：微型列宽仅约 35px，若采用 30 秒则每个数据点仅 1.1px，且 30 秒导致历史旧峰值滞留过久，视觉反馈迟钝；若采用 5~10 秒则滑出过快无法体现趋势。
  - **标准规格**：固定采样间隔为 **1000ms（1秒）**，波形缓冲区设为 **15~20 个点（跨度 15~20 秒）**。单点占据约 1.8~2.3px 宽度，既能完美捕捉一次应用加载、文件编译或网络下载的短时波动，又能自然快速代谢，折线平滑清晰。
  - 内存开销极低（固定大小环形缓冲区 Ring Buffer，仅数十字节），单次渲染耗时 $< 20\,\mu\text{s}$，设置中心支持独立开关。

## 4. 窗口依附、渲染与系统防冲突架构

### 4.1 窗口宿主与 Windows 11/10 任务栏安全依附方案

- **窗口样式**：创建无边框、不抢焦点的分层分级窗口：
  ```rust
  WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE | WS_EX_TOPMOST
  ```
- **依附与定位策略**：
  1. 通过 `FindWindowW("Shell_TrayWnd", ...)` 获取主任务栏句柄；
  2. 获取通知区域托盘句柄 `TrayNotifyWnd`；
  3. 锚定在托盘区域左侧安全边距位置（Windows 10/11 均可稳定锚定）；
  4. 监听宿主位置变动与 `WM_WINDOWPOSCHANGING`，使用 `SetWindowPos` 实现无缝贴靠与平滑位置同步；
  5. **Win11 居中应用图标防遮挡**：检测 Win11 任务栏图标居中/靠左设置与运行中应用图标右边界，当居中应用图标逼近监控面板时，触发自动缩紧或优先向右缩进微调。

### 4.2 全屏应用主动隐匿避让机制（防遮挡关键设计）

针对游戏玩家与演示场景，杜绝 `WS_EX_TOPMOST` 窗口强行置顶遮挡游戏或 PPT：
1. 后台周期性或响应 `EVENT_SYSTEM_FOREGROUND` 检查当前前台窗口句柄 `GetForegroundWindow()`；
2. 检查前台窗口矩形大小：若前台窗口尺寸覆盖了当前屏幕全部分辨率，且窗口类名非桌面（`Progman` / `WorkerW` / `Shell_TrayWnd`）；
3. **判定为全屏游戏/视频/演示**：监控窗立即调用 `ShowWindow(hwnd, SW_HIDE)` 静默隐藏；
4. 当用户切回桌面或普通窗口时，重新调用 `ShowWindow(hwnd, SW_SHOWNA)` 恢复展示。

### 4.3 任务栏“自动隐藏”协同

- 调用 `SHAppBarMessage(ABM_GETSTATE)` 监测任务栏是否处于 `ABS_AUTOHIDE` 模式；
- 在自动隐藏模式下，监听任务栏滑入与滑出坐标，监控窗口同步联动淡出或隐藏，避免悬空停留在屏幕边缘。

### 4.4 渲染引擎与 GDI+ 预乘 Alpha 规范

- 纯 Win32 标准 GDI 的 `DrawTextW` 不支持 32 位 Alpha 通道混合，直接渲染会导致半透明背景下的文字出现严重黑边毛刺。
- **绘制规范**：
  - 复用 QuickPath 已集成的 `Win32_Graphics_GdiPlus`（GDI+）或 DirectWrite；
  - 在内存 32bpp ARGB 位图中使用抗锯齿文本渲染（`TextRenderingHintAntiAliasGridFit`）；
  - 调用 `UpdateLayeredWindow` 进行预乘 Alpha（`AC_SRC_ALPHA`）整体合成上屏；
  - **按需重绘**：数据未变化或窗口隐藏时不调用重绘，杜绝固定高帧率空转功耗。

## 5. 线程模型与与 QuickPath 主程序的架构集成

### 5.1 线程模型与无锁数据流

```text
[QuickPath 主进程]
        │
        ├─► [后台采样 Worker 线程] 
        │         │ (每 1000ms 采样核心指标)
        │         ▼
        │   [无锁共享状态 ArcSwap<MetricsSnapshot>]
        │         │
        │         ▼ (内存快照无锁读取)
        └─► [主线程 Win32 消息循环 (GetMessageW)]
                  │ (SetTimer 1000ms / 收到事件触发)
                  ▼
            [监控窗口 GDI+ 绘制与 Tooltip 更新]
```

- **无锁状态共享**：Worker 线程生成完整的不可变 `MetricsSnapshot` 结构，通过 `arc_swap::ArcSwap` 原子指针交换与主线程共享，完全杜绝线程锁争用与死锁风险。
- **句柄复用**：PDH 查询句柄与网络接口结构仅在初始化时创建，主循环只调用 `PdhCollectQueryData`，杜绝重复分配导致的内存与句柄泄漏。

### 5.2 与 QuickPath 主程序深度集成规范

#### 5.2.1 配置系统整合 ([AppConfig](file:///f:/git/gitea20250909/QuickPath/src/rules/config.rs))

在主程序配置文件结构中平滑加入 `MonitorConfig`，默认开启总开关及各核心指标：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct MonitorConfig {
    /// 任务栏状态监控总开关（默认 true，开启）
    pub enabled: bool,

    // --- 细粒度常驻指标勾选项 ---
    /// 是否显示网络吞吐速率（上行与下行合并为一个设置项，默认 true）
    pub show_network: bool,
    /// 是否显示处理器利用率 (CPU，默认 true)
    pub show_cpu: bool,
    /// 是否显示物理内存利用率 (RAM，默认 true)
    pub show_memory: bool,
    /// 是否显示显卡利用率 (GPU，默认 true)
    pub show_gpu: bool,
    /// 是否显示磁盘利用率 (Disk，默认 true)
    pub show_disk: bool,

    // --- 外观与采样高级设置 ---
    /// 是否显示历史折线波动背景图 (15~20秒采样，默认 true)
    pub show_graph_bg: bool,
    /// 采样刷新间隔（毫秒，默认 1000ms，可选 1000 / 1500 / 2000ms）
    pub refresh_interval_ms: u64,
    /// 界面半透明度（50 ~ 100，默认 85）
    pub opacity: u8,
}

impl Default for MonitorConfig {
    fn default() -> Self {
        Self {
            enabled: true,
            show_network: true,
            show_cpu: true,
            show_memory: true,
            show_gpu: true,
            show_disk: true,
            show_graph_bg: true,
            refresh_interval_ms: 1000,
            opacity: 85,
        }
    }
}
```

#### 5.2.3 设置中心整合 ([SettingsWindow](file:///f:/git/gitea20250909/QuickPath/src/ui/settings.rs))

在 QuickPath Fluent 设置界面中新增“任务栏监控”独立选项卡，提供直观的配置管理卡片：

1. **主控制卡片（总开关）**：
   - `启用任务栏状态监控`（ToggleSwitch 开关，**默认开启**）；
   - *联动逻辑*：当总开关置为“关”时，下方所有卡片项整体置灰禁用（Disabled），并在任务栏即时销毁监控分层窗口。

2. **常驻指标勾选卡片**：
   - `[√] 网络吞吐速率 (上行 / 下行合并)` —— 勾选后展示两行 `↑` 与 `↓` 速率；
   - `[√] 处理器利用率 (CPU)` —— 勾选后展示 `C: xx%` 及微型指示条；
   - `[√] 物理内存利用率 (RAM)` —— 勾选后展示 `M: xx%` 及微型指示条；
   - `[√] 独立显卡利用率 (GPU)` —— 勾选后展示 `G: xx%`（无独显设备自动灰显提示）；
   - `[√] 磁盘吞吐利用率 (Disk)` —— 勾选后展示 `D: xx%`；
   - *即时生效机制*：勾选或取消勾选任意项后，任务栏面板**即时动态重算宽度与重新排布列**，无需重启程序；若用户取消勾选全部 5 个指标，面板自动平滑隐藏，避免出现空白残影。

3. **视觉与高级采样卡片**：
   - `显示实时历史波形背景 (15~20秒)`（Checkbox，默认开启）；
   - `采样刷新频率`（下拉单选：1.0 秒 / 1.5 秒 / 2.0 秒，推荐 1.0 秒）；
   - `面板不透明度`（Slider 滑块，50% ~ 100%，默认 85%）。

#### 5.2.4 零开销休止保障
当用户将 `monitor.enabled` 置为 `false` 时：
1. 监控窗口句柄安全销毁；
2. 采样 Worker 线程安全退出；
3. PDH Query 句柄及网络采集结构完整释放；
4. 保证在用户不需要该功能时，QuickPath 绝不产生任何后台冗余 CPU 占用。

## 6. 异常防御与高可用矩阵

| 边界场景 | 核心风险 | 详细防御与自愈措施 |
| :--- | :--- | :--- |
| **休眠 / 挂起与唤醒** | 唤醒后系统时钟跳变，导致网速和磁盘 I/O 速率计算值溢出爆表 | 监听 `WM_POWERBROADCAST`（`PBT_APMRESUMEAUTOMATIC`）。唤醒后立即丢弃首次时间差计算，强制重置基准时间戳。 |
| **Explorer 崩溃/重启** | 任务栏窗口被重置销毁，监控悬浮窗失去依赖层或被遮盖 | 注册系统全局消息 `RegisterWindowMessageW("TaskbarCreated")`。捕获此消息后重新定位任务栏坐标，重新置顶绑定。 |
| **PDH 计数器失效** | 显卡驱动热更新、动态超频、休眠唤醒使 PDH 查询失效 | 若 `PdhCollectQueryData` 连续 2 次返回错误，后台线程自动关闭旧 Query 句柄并重试初始化，不抛出 Panic。 |
| **网卡拔插 / VPN 切换** | 物理网卡断开或隧道接口变更导致读取计数器越界 | 捕获 API 错误码并优雅降级为 `0.0 B/s`；后台线程每 30 秒重新调用 `GetIfTable2` 校验活跃网卡列表。 |
| **全屏游戏/视频运行** | 置顶窗口遮挡全屏画面，破坏沉浸式体验 | 动态检测前台窗口全屏状态，检测到全屏立即隐藏（`SW_HIDE`），切回桌面即刻自愈恢复。 |
| **显示器热插拔 / DPI 变更** | 外接显示器分辨率变化导致窗口字体模糊或排版挤压 | 响应 `WM_DPICHANGED` 消息，调用 `GetDpiForWindow` 动态获取当前屏幕物理 DPI，按比例自适应缩放字体尺寸与窗体外宽。 |
| **突发断电 / 强行断电** | 配置文件损坏或出现 0 字节损坏文件，导致下次启动失败 | 配置文件变更时使用“写入临时文件 $\to$ 原子替换文件”操作；遇到任何反序列化失败，一律回退至安全默认值。 |

## 7. 质量指标 (SLI / SLO) 与构建目标

- **常驻内存增量 (Working Set)**：模块开启时增量 $\le 5\text{ MB}$（全局进程总内存维持在 $15\sim 20\text{ MB}$ 范围内）。
- **CPU 占用**：闲置与高负荷状态下均维持在 $\le 0.05\%$，单次采样耗时 $\le 2\text{ ms}$。
- **纯原生依赖**：杜绝 C++ 运行时及 WebView/Electron 引入，使用 Rust 标准生态（`windows-rs`、`arc-swap`、GDI+）。
- **可维护性**：代码收敛于 `src/monitor/` 独立子模块，高内聚低耦合，对原有文件对话框秒切逻辑零侵入。
