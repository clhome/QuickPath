## 0. 标记约定与通用说明

- **🔧 必须真机人工执行**：依赖真实 GUI 会话、真实第三方程序（WPS / Explorer / 第三方管理器），
  无法在本仓库的构建/测试环境（无交互桌面）自动化。本清单所有条目默认都是 🔧。
- **✅ 本轮代码侧已覆盖**：可由 `cargo test --all-targets` 在无 GUI 环境验证，列出对应测试名。
- **判据用词**：「零跨窗口输入」= 整个动作期间 QuickPath 没有向**非目标窗口**发送任何全局键鼠事件
  （`keybd_event` / 鼠标点击）；「绝不发 Enter」= 路径回读失败时 Enter 一次都不发送。
- **通用环境准备（每个会话开始前执行一次）**：
  1. Windows 11 23H2 与 24H2 各跑一遍（报告 §12 Explorer 标签页要求）。
  2. 安装 WPS Office（含文字 / 表格 / 演示），版本记录到「证据」栏。
  3. 开启 QuickPath 调试日志，并确认日志文件位置（设置中心 → 常规 → 日志卡片；或
     `%USERPROFILE%\AppData\Local\QuickPath\` 下的调试日志）。日志中的关键锚点：
     `UIA_GUARD`、`UIA_VERIFY`、`UIA_REJECT`、`UIA_FOCUS`、`WINE_TO_TAB`、`APP_STATE_REENTRANT`、
     `CLIPBOARD_OWNER_SHUTDOWN_TIMEOUT`、`COM_DEGRADED`、`COM_RECOVERED`。
  4. 证据采集：录屏（`.mp4`）+ 日志片段（贴入记录栏）+ 必要时截图。失败项必须附日志原文。

## 3. 退出生命周期与竞态（报告 §10-5 + §12「响应性与生命周期」）

> 覆盖目标：退出时保留延迟消息与后台扫描结果，**无 UAF / double-free / 句柄泄漏**；
> 快速退出、启停标签模块 1,000 次、COM 挂起后 worker 重建均可恢复。
> 代码锚点：`src/main.rs` 退出序列（置空 `HOST_HWND` → `UnregisterHotKey` → drop `AppState`
> → `shutdown_clipboard_owner()`）、`src/win32/clipboard.rs`（R-06 owner 退出协议）、
> `src/tab/com.rs`（P-04b 熔断/退避/降级）。

### 3.0 🔧 工具准备（一次性）

在**测试机**（非生产机）上启用堆与句柄校验：

1. **Application Verifier**（推荐）：
   - 打开 `appverif.exe`（Windows SDK 自带）→ File → Add Application → 选择 `QuickPath.exe`。
   - 勾选 **Basics → Heaps、Handles、Locks**（必要时加 `Exceptions`）。
   - Save，然后启动 QuickPath（验证器会在进程启动时注入并记录违规）。
   - 查看结果：Verifier 的 Logs 视图，或 `appverif.exe -export log -for QuickPath.exe`。
2. **PageHeap（gflags）**（与 Verifier 二选一或叠加，用于抓 UAF/double-free 的越界/重复释放）：
   - `gflags.exe /p /enable QuickPath.exe /full`
   - 复现退出流程后：`gflags.exe /p /disable QuickPath.exe`（务必还原，full page heap 会显著增大内存占用）。
3. **崩溃转储**：用 ProcDump 捕获未处理异常：
   - `procdump.exe -accepteula -e -ma -x <dump目录> QuickPath.exe`
4. **句柄泄漏观察**：Process Explorer（`procexp.exe`）观察 QuickPath 进程的 Handles/GDI/User 对象计数；或 WinDbg `!htrace -enable` + `!htrace -diff`。
5. **判据（本清单通用）**：无崩溃、无 Verifier 断言、无 PageHeap 的 `HEAP_CORRUPTION`/`double free` 报告、无句柄/GDI/User 对象持续增长告警。

### L-01 🔧 快速退出：保留延迟消息与后台扫描结果，无 UAF / double-free

- **前置条件**：已启用 PageHeap / Application Verifier（3.0）。
- **操作步骤**：
  1. 让 QuickPath 处于高活动态：连续 Win+E、反复切换文件管理器触发后台扫描、触发若干次延迟重试（`WM_QUICKPATH_RETRY_CHECK` / `WM_QUICKPATH_INJECT_FAILED` 的 250ms 延迟线程）。
  2. 在延迟消息与后台扫描**尚未回传**的瞬间，从托盘菜单选择「退出」（`IDM_EXIT` → `PostQuitMessage`）。
  3. 观察进程退出过程与 Verifier / PageHeap 报告。
- **期望判据**：
  - 退出序列按设计执行：`HOST_HWND` 置空拦截未决投递 → `UnregisterHotKey` → drop `AppState`（后台扫描 `send` 失败自然丢弃，不泄漏）→ `shutdown_clipboard_owner()`。
  - **无 UAF / double-free**（PageHeap 无 `double free`/`invalid pointer` 报告）；无 Verifier 断言；进程正常退出（退出码 0），不挂起。
  - 后台线程若已无接收端，`send` 失败即丢弃，**不出现 panic / abort**。
- **记录栏**：结果 ☐ 通过 ☐ 失败　证据（Verifier/PageHeap 日志片段）：________

## 8. 本轮（P0-03 / M-01 / P2-4.1）新增的观察点与诚实声明

### 8.1 必须真机观察的新增点

- **S-01 🔧 owner 取消握手残余风险**：`owner` 就绪等待超时后的取消握手，若 `CreateWindowExW` 前置调用
  真的挂起超过 2s，有界确认会超时 → 记 `CLIPBOARD_OWNER_TIMEOUT_CANCEL` 后仍 detach。
  **观察方法**：正常使用后退出 QuickPath，检查是否残留线程 / 隐藏窗口：
  `Get-Process quickpath | Select-Object -ExpandProperty Threads | Measure-Object`（退出后进程应消失）
  或 Spy++ 查 `QuickPath_ClipboardOwner_Class`；**不应残留**。日志中不应出现 `CLIPBOARD_OWNER_TIMEOUT_CANCEL`。
- **S-02 🔧 严格 sequence 的副作用（设计权衡）**：事务的归属判定**只认** `GetClipboardSequenceNumber`，
  因此**剪贴板管理器**在事件后附加自有格式（即使内容未变）也会 bump 序列号 → 被判为「外部改写」
  → 事务中止扫描 / 跳过恢复。这是**刻意的 fail-safe 方向**（宁可少恢复，不可覆盖用户内容），
  但需真机确认**不会频繁误触发**。**观察方法**：装一个剪贴板管理器（如 Ditto / ClipboardFusion），
  正常使用后统计日志中 `CLIPBOARD_PROBE_ABORTED` / `CLIPBOARD_RESTORE_SKIPPED` 的出现频率；
  若「非用户复制」也频繁触发，需回来重新权衡策略。
- **S-03 🔧 空闲 CPU 与分位数采集（服务报告 §4.2 决策）**：`src/managers/scanner.rs` 已输出聚合遥测
  （`SCAN_STATS:` 每 500 次、`SCAN_TELEMETRY:` 每 500 次前台事件），可直接用于采集报告 §4.2 的
  5 项指标（Win+E 回调 P99 / 宿主阻塞 P99 / 首扫 P95 / 空闲 CPU / 预算耗尽率）。
  **压测时同步收集这些日志**，作为「是否按管理器拆分 scanner worker」的决策输入。

### 9.2 C-08 竞态 A：写前校验与写入之间的原子性

### 9.3 C-09 竞态 B（用户复制先、管理器覆盖后）

- **步骤**：在 TC 双面板（或 XY）前台时，**先**复制一段唯一文本，**紧接着**触发 QuickPath 扫描

- **判据**：
  - 日志出现 `CLIPBOARD_PROBE_ABORTED(totalcmd|xyplorer)` 的轮次，剪贴板**保留用户内容**（旧快照未写回）；
  - **不得**出现「用户复制的唯一文本被静默替换为管理器路径且未记任何 abort/skip 日志」。

    但日志如实记录 abort；这种情形记录轮次数与复现概率。
- **自动化覆盖**：`test_probe_rejects_foreign_update_before_manager_write`、
  `test_probe_rejects_foreign_final_owner_after_manager_write`（✅ 不替代真机）。

### 9.4 C-10 目标管理器 owner 归属的真实性（可用性关键）

- **步骤**：启用 TC 与 XY 的路径跟随，正常使用 100 次，收集日志。
- **判据**：不得出现「管理器已正常响应、路径可取回，但被 `OwnershipUnknown` / `NotOwned` 拒绝」的
  持续失败（表现为跟随功能时好时坏或完全失效，且日志频繁 abort）。
- **若失败**：说明该管理器写剪贴板时 `GetClipboardOwner()` 非其本进程窗口（例如 `OpenClipboard(NULL)`
  或经辅助进程），需要回来调整来源判定策略（例如退回「仅最终 owner 校验」并记录为独立风险）。
- **这是本轮最需要真机确认的一项**：来源判定在无法归因时一律 fail-closed（宁可不认领），可用性依赖
  「目标管理器确实以自身进程的窗口成为剪贴板 owner」。

### 9.5 C-11 事件链固有极限的影响面

- **步骤**：用 `Ctrl+C` 制造「用户复制」后，**在 1ms 内**让管理器覆盖（可用工具脚本）；重复 200 轮。

- **诚实边界（必须写进验收结论）**：`WM_CLIPBOARDUPDATE` 是**投递**消息，系统可能把两次快速更新
  合并为一次通知；此时无法区分中间那次写入的来源，最终 owner 若恰为目标管理器则无法检出。
  这是 Windows 全局剪贴板协议层面的限制，**不是 QuickPath 写回旧快照造成的覆盖**。
  若该概率不可接受，正确做法是放弃用全局剪贴板作后台查询通道（改为显式、前台、用户触发的短事务），
  而不是继续收紧归属判定。

## 12. 未解决问题报告 `83bd49b` 轮新增项（P0-06 / U-01A / D-01A / D-01B / S-LOG-A）

> 背景：本轮新增 **进程级独占 lease**（P0-06）、把目标解析改为**不可变触发快照**
> （U-01A）、撤下“绝不覆盖”绝对承诺（D-01A）、补齐四页签文档（D-01B）、
> 收口 UIA 元数据脱敏（S-LOG-A）。以下为仍需真机确认的部分。

### Q-01 🔧 并发快速点击只能有一次探测进入事务（P0-06 核心）

- **步骤**：
  1. 切到 TC 并在剪贴板里放一段可辨认的原文本（例如 `QP_ORIGINAL_<时间戳>`）；
  2. 右键托盘图标后，**以最快速度连点两次**「从 TC 获取当前路径」；
  3. 同样对 XYplorer 重复一遍，并额外做一次「TC 与 XY 交叉快速点击」；
  4. 再对悬浮吸附条顶栏 `[TC]` 连点两次。
- **判据**：
  - 只有一个请求真正执行；第二个请求被拒绝（日志 `EXPLICIT_PROBE_ALREADY_RUNNING(...)`），
    且探测进行中两个入口都置灰（吸附条按钮显示 `…`）；
  - 结束后剪贴板内容回到 `QP_ORIGINAL_<时间戳>`（不被管理器路径取代）；
  - 用 Process Monitor 观察：被拒绝的那一次**不得出现** `EmptyClipboard` / `SetClipboardData`。
- **自动化覆盖**：`test_second_probe_is_rejected_with_zero_clipboard_touch`（确定性 barrier：
  首个请求暂停在「已写空、未收到回写」，第二个请求必须 `AlreadyRunning` 且序列号不变）、
  `test_lease_is_exclusive_and_non_blocking`、`test_lease_releases_on_panic_unwind`、
  `test_lease_is_acquired_before_any_clipboard_transaction`。
- **诚实登记**：自动化只能证明「被拒绝的第二个请求零触碰」；「真实管理器并发回写时原内容
  不丢」仍取决于 §10 D-02/D-03 的真机结论。

### Q-02 🔧 四类剪贴板格式在并发压力下都按首事务结局处理

- **步骤**：分别把原剪贴板设为 ① 纯文本 ② 文件列表（CF_HDROP）③ 位图 ④ 混合格式（文本 + HTML + 自定义格式），
  每种做 100 轮「快速双击 + 立刻手工复制新内容」；
- **判据**：不存在一次旧快照覆盖；剩余剪贴板结果与文档描述一致（成功 = 原内容或管理器路径，
  异常 = 不覆盖）；日志只有结构化结局，不含路径 / 正文。
- **自动化覆盖**：§10 既有事务用例 + `test_probe_*_restores_all_seeded_formats` 系列。

### Q-03 🔧 托盘严格前台与吸附条事件绑定的差异可被用户感知

- **步骤**：
  1. 在 TC 为前台时右键托盘 → 菜单项可点，探测成功，若当时无对话框则弹出气泡「已获取管理器当前路径」；
  2. 切到记事本后右键托盘 → TC 项置灰；
  3. 先进入 TC，再切到某应用打开“另存为”对话框 → 吸附条顶栏出现 `[TC]`；点它 → 探测成功；
  4. 关闭该对话框再打开另一个 → 确认顶栏按钮重新冻结（不会沿用上一个对话框的目标）。
- **判据**：①②③④ 均与手册「管理器联动」页描述一致；取消 / 超时 / 来源不可证明时
  弹出气泡「未取得路径（已取消或超时）」。
- **自动化覆盖**：`test_tray_trigger_snapshot_is_single_use`、
  `test_bar_targets_are_generation_bound`、`test_tray_probe_result_i18n_present_in_both_locales`。

### Q-04 🔧 “用户先复制 B、管理器后写 C”时 QuickPath 不恢复旧快照（D-01A）

- **步骤**：点下“获取当前路径”后立刻手工 `Ctrl+C` 复制 B，等待管理器回写路径 C。
- **判据**：QuickPath **不会**把快照 A 写回（剪贴板最终是 C）；文档不再承诺“绝不覆盖 / 无损”。
- **自动化覆盖**：§10 D-02/D-04 既有用例；文档口径由 `grep` 复查（见修复记录 §5）。
