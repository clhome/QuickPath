# 真机验收清单：竞态与生命周期（v1.2.3）

> **依据**：`test/QuickPath_审计评分报告_v1.2.3.md` §10「仍需补齐的高价值测试」第 3、4、5 条，
> 以及 §12「Windows 11 发布前验收清单」中的「WPS 与标准对话框」「Explorer 标签页」「响应性与生命周期」三节。
>
> **性质声明**：本清单是**人工验收步骤**，用于在真实 Windows 11 + 真实 WPS Office + 真实资源管理器
> 上判定竞态与资源生命周期是否清零；它**不替代代码测试**，也不作为自动化门禁。
> 代码侧能自动化的部分已在本轮 commit（t9）中以单元测试覆盖，见 §5。
>
> **每条都必须可判定、可记录**：给出「前置条件 / 操作步骤 / 期望判据 / 记录栏（通过 / 失败 / 证据）」。
> 操作步骤中的**对抗动作**（快速 Alt+Tab、关闭目标窗口、PID 变化、HWND 复用）是刻意制造竞态，
> 不是正常路径。

## 0. 标记约定与通用说明

- **🔧 必须真机人工执行**：依赖真实 GUI 会话、真实第三方程序（WPS / Explorer / 第三方管理器），
  无法在本仓库的构建/测试环境（无交互桌面）自动化。本清单所有条目默认都是 🔧。
- **✅ 本轮代码侧已覆盖**：可由 `cargo test --all-targets` 在无 GUI 环境验证，列出对应测试名。
- **判据用词**：「零跨窗口输入」= 整个动作期间 QuickPath 没有向**非目标窗口**发送任何全局键鼠事件
  （`keybd_event` / 鼠标点击）；「绝不发 Enter」= 路径回读失败时 Enter 一次都不发送。
- **通用环境准备（每个会话开始前执行一次）**：
  1. Windows 11 23H2 与 24H2 各跑一遍（报告 §12 Explorer 标签页要求）。
  2. 安装 WPS Office（含文字 / 表格 / 演示），版本记录到「证据」栏。
  3. 开启 QuickPath 调试日志，并确认日志文件位置（设置中心 → 常规 → 日志卡片；或
     `%USERPROFILE%\AppData\Local\QuickPath\` 下的调试日志）。日志中的关键锚点：
     `UIA_GUARD`、`UIA_VERIFY`、`UIA_REJECT`、`UIA_FOCUS`、`WINE_TO_TAB`、`APP_STATE_REENTRANT`、
     `CLIPBOARD_OWNER_SHUTDOWN_TIMEOUT`、`COM_DEGRADED`、`COM_RECOVERED`。
  4. 证据采集：录屏（`.mp4`）+ 日志片段（贴入记录栏）+ 必要时截图。失败项必须附日志原文。

## 1. WPS 对抗切换（报告 §10-3 + §12「WPS 与标准对话框」）

> 覆盖目标：WPS 自绘对话框在 **Ctrl+A 前 / Ctrl+A 后 / Ctrl+V 前 / Ctrl+V 后 / 路径回读期间 /

## 3. 退出生命周期与竞态（报告 §10-5 + §12「响应性与生命周期」）

> 覆盖目标：退出时保留延迟消息与后台扫描结果，**无 UAF / double-free / 句柄泄漏**；
> 快速退出、启停标签模块 1,000 次、COM 挂起后 worker 重建均可恢复。
> 代码锚点：`src/main.rs` 退出序列（置空 `HOST_HWND` → `UnregisterHotKey` → drop `AppState`
> → `shutdown_clipboard_owner()`）、`src/win32/clipboard.rs`（R-06 owner 退出协议）、
> `src/tab/com.rs`（P-04b 熔断/退避/降级）。

### 3.0 🔧 工具准备（一次性）

在**测试机**（非生产机）上启用堆与句柄校验：

1. **Application Verifier**（推荐）：
   - 打开 `appverif.exe`（Windows SDK 自带）→ File → Add Application → 选择 `QuickPath.exe`。
   - 勾选 **Basics → Heaps、Handles、Locks**（必要时加 `Exceptions`）。
   - Save，然后启动 QuickPath（验证器会在进程启动时注入并记录违规）。
   - 查看结果：Verifier 的 Logs 视图，或 `appverif.exe -export log -for QuickPath.exe`。
2. **PageHeap（gflags）**（与 Verifier 二选一或叠加，用于抓 UAF/double-free 的越界/重复释放）：
   - `gflags.exe /p /enable QuickPath.exe /full`
   - 复现退出流程后：`gflags.exe /p /disable QuickPath.exe`（务必还原，full page heap 会显著增大内存占用）。
3. **崩溃转储**：用 ProcDump 捕获未处理异常：
   - `procdump.exe -accepteula -e -ma -x <dump目录> QuickPath.exe`
4. **句柄泄漏观察**：Process Explorer（`procexp.exe`）观察 QuickPath 进程的 Handles/GDI/User 对象计数；或 WinDbg `!htrace -enable` + `!htrace -diff`。
5. **判据（本清单通用）**：无崩溃、无 Verifier 断言、无 PageHeap 的 `HEAP_CORRUPTION`/`double free` 报告、无句柄/GDI/User 对象持续增长告警。

### L-01 🔧 快速退出：保留延迟消息与后台扫描结果，无 UAF / double-free

- **前置条件**：已启用 PageHeap / Application Verifier（3.0）。
- **操作步骤**：
  1. 让 QuickPath 处于高活动态：连续 Win+E、反复切换文件管理器触发后台扫描、触发若干次延迟重试（`WM_QUICKPATH_RETRY_CHECK` / `WM_QUICKPATH_INJECT_FAILED` 的 250ms 延迟线程）。
  2. 在延迟消息与后台扫描**尚未回传**的瞬间，从托盘菜单选择「退出」（`IDM_EXIT` → `PostQuitMessage`）。
  3. 观察进程退出过程与 Verifier / PageHeap 报告。
- **期望判据**：
  - 退出序列按设计执行：`HOST_HWND` 置空拦截未决投递 → `UnregisterHotKey` → drop `AppState`（后台扫描 `send` 失败自然丢弃，不泄漏）→ `shutdown_clipboard_owner()`。
  - **无 UAF / double-free**（PageHeap 无 `double free`/`invalid pointer` 报告）；无 Verifier 断言；进程正常退出（退出码 0），不挂起。
  - 后台线程若已无接收端，`send` 失败即丢弃，**不出现 panic / abort**。
- **记录栏**：结果 ☐ 通过 ☐ 失败　证据（Verifier/PageHeap 日志片段）：________

## 5. 本轮（t9）代码侧已覆盖的部分（✅ 不替代真机）

以下项可在无 GUI 环境由 `cargo test --all-targets` 验证，是上述真机条目的**决策逻辑**证据，
但**不能**替代真实 Windows 集成验收：

- **Win+E 失败分支决策**（对应 §10-4，E-02 的决策层）：
  - `wine_to_tab_baseline_unknown_falls_back_without_trying_new_tab`（基线未知 → 原生兜底且不尝试新建）
  - `wine_to_tab_not_accepted_falls_back_once`（接管被拒 → 兜底 1 次）
  - `wine_to_tab_count_always_unreadable_falls_back_once`（计数始终不可读 → 兜底 1 次）
  - `wine_to_tab_count_never_increases_falls_back_once`（计数始终不增 → 兜底 1 次）
  - `wine_to_tab_count_increases_after_unreadable_succeeds_without_compensation`（先不可读后大于基线 → 成功、零补偿）
  - `wine_to_tab_count_increases_immediately_succeeds_without_compensation`（立即大于基线 → 成功、零补偿）
  - `wine_to_tab_failure_inputs_compensate_exactly_once`（**补偿恰好一次**不变量：绝不静默失败、也不重复弹窗）
  - 抽取的纯决策函数：`run_wine_to_tab_sequence(count_before, try_accept, count_after, wait, compensate) -> WineToTabOutcome`。
- **R-06 owner 线程退出协议**（对应 §12 生命周期、L-01/L-03 的代码侧）：
  - `test_owner_shutdown_and_recreate_cycle`、`test_owner_shutdown_is_idempotent_when_absent`
    （`src/win32/clipboard.rs`；`WM_CLOSE` → `WM_DESTROY` → `PostQuitMessage` + 有界 join）。
- **P-04b 熔断 / 退避 / 降级**（对应 E-04 / L-04 的代码侧）：
  - `src/tab/com.rs` 的重建硬上限、指数退避、Open/HalfOpen/Closed 三态；相关降级测试。
- **注入决策与安全守卫**（对应 W-01 ~ W-08 的决策层）：
